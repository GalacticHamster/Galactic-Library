# Privacy policy

Galactic Library stores its library database locally in the current Chrome profile. It has no developer-operated server, analytics, advertising, affiliate links, account system, or cloud synchronization.

The Steam importer reads game and DLC IDs, titles, and DLC parent App IDs only after the user selects **Sync Steam library** on Steam Store while signed in. It reads the account's owned App IDs, then sends those IDs to Steam's own StoreBrowse title service to resolve entries Steam identifies as games or DLC. The GOG importer reads game IDs, titles, and platform support only after the user selects **Sync GOG library** on GOG while signed in. It reads GOG's paginated owned-games library, including hidden games when GOG reports them. The Epic importer reads game and add-on IDs, titles, platforms, and add-on parent IDs only after the user selects **Sync Epic library** on Epic Games Store while signed in. It reads the signed-in Epic library and excludes Unreal Engine assets, private/test entries, and items Epic does not identify as games or add-ons. The Audible importer reads audiobook IDs, titles, a sanitized Audible title-page URL, and any displayed author, narrator, and series metadata only after the user selects **Sync Audible library** on Audible while signed in. It makes same-site requests to paginate the Audible Library. Audible items are stored with an unknown ownership state because Audible's library page does not reliably label each title as purchased or membership-included. The Kindle importer reads book and personal-document IDs, titles, available authors, series, collections, acquisition dates, entitlement sources, and available publisher, publication-date, and format fields only after the user selects **Sync Kindle library** on Amazon while signed in. It makes same-site requests to the Amazon Content & Devices Books and Personal Documents libraries and does not bulk-request individual product pages. Kindle purchases are stored as owned; Kindle Unlimited, Prime, rental, and trial titles are stored as subscription records; personal documents are stored with an unknown ownership state. None of the importers asks for, copies, or stores a provider password, cookie, or OAuth/Web API token or device authorization. Future provider importers will follow the same signed-in, user-initiated model. Backups are created only when the user explicitly selects Export and are restored only when the user explicitly selects a file.

Stored data will include provider item identifiers, titles, ownership state, provider metadata necessary for the library, sync timestamps, and user match decisions. Data remains until the user clears it, restores another backup, or uninstalls the extension.
