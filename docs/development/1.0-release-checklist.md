### B1 termination protocol and live retest

**Confirmed history:** The first Firefox Full rescan incorrectly certified 150 movies + 30 TV titles. The user manually counted 302 movies + 41 TV shows; Amazon did not report 343. An initial read-only export found 343 across 19 passes, including a two-pass plateau at 180. A later Full rescan saved all 343, while Quick update after the bad baseline had found no additions. The format-3 export then found all 343 by pass 14, observed no further discoveries in the remaining 236 passes, and ended unconfirmed at pass 250. The older Chrome backup has 339 distinct records (298 movies/41 TV titles); it is historical comparison evidence, not a completion oracle.

**Root causes:** The original code confused a current scroll boundary plus three quiet polls with the collection's terminal boundary. `d1ba434` removed that unsafe inference but made a provider total mandatory; the real page supplied no recognized total, so normal convergence could never finish. Full scans and read-only checks share traversal, so the earlier different outcomes do not establish different parsers. Exact timing of the unexported first failure remains unknown.

**Available evidence and limits:** The latest live export uses the document scroller, reports no separate vertical containers, has only 67 cards in the final DOM despite 343 cumulative IDs, and shows zero recognized loading/Next controls at the end. Earlier exports show scroll-range extensions after apparent exhaustion. This supports asynchronous loading/recycled viewports; it does not reveal the website's internal implementation. Repository inspection shows DOM-card acquisition, not a cursor or application-state adapter. The exports contain no request lifecycle, cursor, structured application state or explicit end-marker contract. No authoritative count, cursor exhaustion or terminal marker has been demonstrated, and absence from these diagnostics is not proof none exists. No speculative API, credential handling or permissions were added.

**Implemented termination protocol:**

1. Traverse overlapping viewports across all detected vertical title lists, accumulating distinct source IDs in memory. A three-poll boundary candidate starts validation; it cannot itself certify completion.
2. At that candidate, scroll back one viewport and attempt to advance beyond the boundary. Check actual movement, range changes, tail membership and pending library controls. New items or range extensions invalidate the candidate and resume discovery.
3. Reset to the start and perform a full verification sweep. Require every previously discovered ID to be revisited, no additional IDs, the same terminal rendered membership and scroll ranges, exhausted relevant containers, and clear loading/continuation checks. New observations restart discovery and validation; conflicting/incomplete verification ends uncertain promptly. Perpetual growth/unstable traversal retains the 250-pass emergency cap.
4. Classify the result explicitly. A consistent, scoped whole-list label matching observed membership can still confirm completion. Without one, successful active probes plus an independently revisitable, converged sweep infer completion. This does not prove arbitrarily late content cannot arrive. No account-specific item or pass count is used in production.

| Outcome | Evidence / termination | Persistence |
| --- | --- | --- |
| Confirmed | Whole-list count reconciles, stable boundary, no pending continuation. No such live count is currently established. | Existing validated full replacement; missing records can move to history under the normal scoped rules. |
| Inferred | Boundary back/forward probe plus complete matching verification sweep, stable ranges/tail, no pending continuation. | Amazon Video's writer validates the snapshot, then uses additive reconciliation under the existing lease/account/stale-save guards. No unseen record is retired. Existing sync-health coverage limitation records this qualification. |
| Uncertain | Verification cannot revisit membership, geometry/continuation disagrees, count conflicts, or emergency budget is reached. | No observations imported or replaced. Read-only checks can return/export partial observations. |
| Failed | Actual extraction/navigation/other operational error. | No observations imported; existing failure reporting remains. |

The qualified inferred path is a practical safe reconciliation, not an authoritative replacement masquerading as certainty. Older unseen entries may remain current until separately confirmed absent; current-versus-history rules are unchanged for confirmed replacements. Source identifiers, manual edits, account boundaries, purchase/rental/access parsing and other providers are unchanged. No schema migration is needed. Quick update remains newest-only and cannot repair older gaps from a bad baseline.

**Diagnostics:** Format 4 retains new/cumulative and movie/TV counts, per-phase scroll target/movement/range, recognized loading controls, boundary-probe results, verification start/end/revisited/missing/new membership counts, range/tail checks, classification and stop reason. No titles, product IDs, account identifiers, URLs or credentials are exported. Read-only checks still create no sync lease or saved library changes.

**Validation:** `node tests/browser.js --release --amazon-video` and the same command with `--firefox` each pass 63 synthetic packaged-browser checks. The delayed-180 fixture does not finish there; the scroll-driven 343-item fixture revisits all identities and terminates through convergence, with test bounds far below 250. Non-revisitable virtual content stays uncertain, and persistent busy/more controls stop via failed verification instead of spinning. Tests cover returning loading indicators, late range extensions, separate scrollers, navigation errors, unchanged repeats and additive preservation. Two worker regressions exercise same-account inferred merges, other-account/provider isolation, stale commits, malformed proofs and confirmed retirement. These are disposable fixtures, not live Amazon validation.

**Minimal live retest (Firefox first):**

1. Reload the rebuilt extension and Amazon Video **My Stuff > Purchases & Rentals**, with filters cleared.
2. Run **Scan diagnostics > Check listing (no import)** and export. Expect either a qualified inferred end after a probe and complete verification sweep, or an actionable uncertain result explaining the mismatch. It should not sit at 343 until pass 250. Compare observed movie/TV totals with the current grid; the earlier manual reference was 302/41, not an input to GL.
3. With a backup retained, run Firefox **Full rescan**. An inferred result must say so and keep earlier saved titles; a confirmed result may replace; an uncertain/failed result must leave source membership intact. Repeat unchanged and verify the same classification/membership. Export any unexpected outcome.
4. Repeat the read-only check in Chrome for parity before changing the authoritative Chrome library. Quick update remains a bounded newest-title check, not full-baseline repair.

Firefox results are now reported above; B1 remains open for Chrome parity. If the real page cannot revisit its earlier virtualized contents, use the uncertainty diagnostics to identify that limitation; do not remove the verification requirement or substitute a longer idle threshold. The temporary provider diagnostics can be consolidated during later UI cleanup.

### B4 purchase-label repair and remaining live evidence

**Code findings:** The importer read card text only, matched the broad word "purchase", and retained only the first observation per source ID. The old implementation neither requested hover details nor inspected structured application state. Refreshed Unknown observations could overwrite saved purchase evidence. The storage writer now preserves an earlier known access observation when a later observation supplies no access evidence, in both additive and confirmed scan paths. An explicit new access state still applies; user ownership reviews remain separate and authoritative.

**Bounded implementation:** Read individual card-local entitlement labels, including hidden text, instead of classifying joined card prose. Recognize "You purchased this", existing explicit Purchased/Owned labels, explicit rental labels, and narrowly stated subscription labels. Purchase offers and episode-only wording are not full-product evidence. A TV purchase requires a season entity or an explicit numbered Season title; a generic TV_SHOW is not promoted to whole-series ownership. Retain delayed labels while scanning and across virtualized remounts by stable source ID. Traversal boundaries and completion checks are unchanged. Quick update remains newest-only; use Full rescan for existing-record enrichment.

**Live evidence:** `GL-amazon-video-scan(3).json` reports seven recognized purchases and 65 unconfirmed among 72 observed cards after user hovering, with zero unassociated purchase labels. It is a read-only sample, not a full-library ownership audit, and does not reveal whether Amazon obtained those labels through a request or application state. The newly added opt-in automated hover path still needs live validation.

**Limits:** There is no partial-season ownership state or verified episode acquisition in this adapter. Buy-only seasons remain Unknown, with their original identity retained. No receipts, dates, episode ownership, undocumented API contract, or application state are invented. The optional **Read purchase labels while scanning (slower)** setting dispatches ordinary pointer/mouse hover events once per unconfirmed stable source ID, waits at most 600 ms, and reads only the same card. It never clicks or constructs API calls. Missing or late labels remain unconfirmed; late card-local mutations during the scan are still retained. The upper waiting cost for 343 unconfirmed cards is approximately 206 seconds, plus normal traversal. It is off by default until live validation; no account preference or schema change is introduced. If Amazon mounts details in an unassociated overlay, those labels are diagnostic only and cannot safely establish ownership yet. Unassociated overlays, page handlers that reject synthetic events, or details arriving after the bounded check may require a further validated adapter. No undocumented API or structured-state contract is assumed; this is not claimed live-complete.

**Minimal Firefox check:** Reload the extension and Amazon Video page. Open **Scan diagnostics > Check purchase labels (no import)**. During its 15 seconds, hover a known purchased movie, a fully purchased season, and a season with only purchased episodes. Export diagnostics. The report contains aggregate states and unassociated purchase-label counts, no titles or identifiers, and makes no library writes. The first sample recognized seven card-local purchases. Next enable **Read purchase labels while scanning (slower)** and run **Check listing (no import)**; export the aggregate ownership and hover checks. Only after this read-only validation, retain a backup, run Full rescan with the option enabled, inspect those three records, repeat unchanged, and verify 343 source records with retained manual corrections. Do not treat the diagnostic's currently observed-card total as the full-library total.

**Validation:** 1,685 unit tests and 485 contents tests pass. Packaged Chrome and Firefox each pass 78 targeted Amazon Video, 105 importer, and 68 main-UI checks; both 218-file packages and repository checks pass. Synthetic unit/worker and packaged Chrome/Firefox fixtures cover card-local and delayed labels, Buy-only seasons, rentals, virtual remounts, adjacent-card isolation, existing identity upgrades, sparse rescans, manual overrides and backup restoration. These establish code behavior, not live purchase classification. B4 remains open until representative live results confirm it.
