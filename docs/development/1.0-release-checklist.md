### B1 termination protocol and live retest

**Confirmed history:** The first Firefox Full rescan incorrectly certified 150 movies + 30 TV titles. The user manually counted 302 movies + 41 TV shows; Amazon did not report 343. An initial read-only export found 343 across 19 passes, including a two-pass plateau at 180. A later Full rescan saved all 343, while Quick update after the bad baseline had found no additions. The format-3 export then found all 343 by pass 14, observed no further discoveries in the remaining 236 passes, and ended unconfirmed at pass 250. The older Chrome backup has 339 distinct records (298 movies/41 TV titles); it is historical comparison evidence, not a completion oracle.

**Root causes:** The original code confused a current scroll boundary plus three quiet polls with the collection's terminal boundary. `d1ba434` removed that unsafe inference but made a provider total mandatory; the real page supplied no recognized total, so normal convergence could never finish. Full scans and read-only checks share traversal, so the earlier different outcomes do not establish different parsers. Exact timing of the unexported first failure remains unknown.

**Available evidence and limits:** The latest live export uses the document scroller, reports no separate vertical containers, has only 67 cards in the final DOM despite 343 cumulative IDs, and shows zero recognized loading/Next controls at the end. Earlier exports show scroll-range extensions after apparent exhaustion. This supports asynchronous loading/recycled viewports; it does not reveal the website's internal implementation. Repository inspection shows DOM-card acquisition, not a cursor or application-state adapter. The exports contain no request lifecycle, cursor, structured application state or explicit end-marker contract. No authoritative count, cursor exhaustion or terminal marker has been demonstrated, and absence from these diagnostics is not proof none exists. No speculative API, credential handling or permissions were added.

**Implemented termination protocol:**

1. Traverse overlapping viewports across all detected vertical title lists, accumulating distinct source IDs in memory. A three-poll boundary candidate starts validation; it cannot itself certify completion.
2. At that candidate, scroll back one viewport and attempt to advance beyond the boundary. Check actual movement, range changes, tail membership and pending library controls. New items or range extensions invalidate the candidate and resume discovery.
3. Reset to the start and perform a full verification sweep. Require every previously discovered ID to be revisited, no additional IDs, the same terminal rendered membership and scroll ranges, exhausted relevant containers, and clear loading/continuation checks. New observations restart discovery and validation; conflicting/incomplete verification ends uncertain promptly. Perpetual growth/unstable traversal retains the 250-pass emergency cap.
4. Classify the result explicitly. A consistent, scoped whole-list label matching observed membership can still confirm completion. Without one, successful active probes plus an independently revisitable, converged sweep infer completion. This does not prove arbitrarily late content cannot arrive. No account-specific item or pass count is used in production.

| Outcome | Evidence / termination | Persistence |
| --- | --- | --- |
| Confirmed | Whole-list count reconciles, stable boundary, no pending continuation. No such live count is currently established. | Existing validated full replacement; missing records can move to history under the normal scoped rules. |
| Inferred | Boundary back/forward probe plus complete matching verification sweep, stable ranges/tail, no pending continuation. | Amazon Video's writer validates the snapshot, then uses additive reconciliation under the existing lease/account/stale-save guards. No unseen record is retired. Existing sync-health coverage limitation records this qualification. |
| Uncertain | Verification cannot revisit membership, geometry/continuation disagrees, count conflicts, or emergency budget is reached. | No observations imported or replaced. Read-only checks can return/export partial observations. |
| Failed | Actual extraction/navigation/other operational error. | No observations imported; existing failure reporting remains. |

The qualified inferred path is a practical safe reconciliation, not an authoritative replacement masquerading as certainty. Older unseen entries may remain current until separately confirmed absent; current-versus-history rules are unchanged for confirmed replacements. Source identifiers, manual edits, account boundaries, purchase/rental/access parsing and other providers are unchanged. No schema migration is needed. Quick update remains newest-only and cannot repair older gaps from a bad baseline.

**Diagnostics:** Format 4 retains new/cumulative and movie/TV counts, per-phase scroll target/movement/range, recognized loading controls, boundary-probe results, verification start/end/revisited/missing/new membership counts, range/tail checks, classification and stop reason. No titles, product IDs, account identifiers, URLs or credentials are exported. Read-only checks still create no sync lease or saved library changes.

### B4 purchase-label repair and remaining live evidence

**Code findings:** The importer read card text only, matched the broad word "purchase", and retained only the first observation per source ID. The old implementation neither requested hover details nor inspected structured application state. Refreshed Unknown observations could overwrite saved purchase evidence. The storage writer now preserves an earlier known access observation when a later observation supplies no access evidence, in both additive and confirmed scan paths. An explicit new access state still applies; user ownership reviews remain separate and authoritative.

**Bounded implementation:** Read individual card-local entitlement labels, including hidden text, instead of classifying joined card prose. Recognize "You purchased this", existing explicit Purchased/Owned labels, explicit rental labels, and narrowly stated subscription labels. Purchase offers and episode-only wording are not full-product evidence. An explicit purchase label establishes ownership of that exact stable provider product ID, including TV products named by volumes, parts, written season numbers or standalone set names. It does not grant ownership to other seasons, episodes or same-title source IDs. The earlier numeric-season gate was an importer false negative and has been removed; no title-only ownership inference replaces it. Retain delayed labels while scanning and across virtualized remounts by stable source ID. Traversal boundaries and completion checks are unchanged. Quick update remains newest-only; use Full rescan for existing-record enrichment.

**Live evidence:** `GL-amazon-video-scan(3).json` reports seven recognized purchases and 65 unconfirmed among 72 observed cards after user hovering, with zero unassociated purchase labels. It is a read-only sample, not a full-library ownership audit, and does not reveal whether Amazon obtained those labels through a request or application state. The subsequent full read-only export `(4)` found all 343 titles and verified membership, but recognized zero purchases in 343 synthetic outer-card hover attempts. This is a failed live ownership-acquisition test, not a successful ownership repair. No import occurred. The follow-up short check samples at most three visible cards using artwork/link event targets, then observes physical mouse target types and label timing. It exports no source IDs or titles. Automatic acquisition remains pending until this passes; do not recommend another full hover pass on the strength of fixtures alone.

**Current behavior and limits:** Purchase-label extraction is automatic for Full rescan and newly discovered Quick-update products. Quick update still stops at a wholly saved group and does not refresh historical ownership or repair older gaps. Hover events target the working artwork/link path once per eligible stable source ID; there is no extra traversal or delay after a purchase is recognized. Unavailable or Prime-only details retain the existing 600 ms bound; Prime availability does not terminate a purchase check prematurely. Previously confirmed purchases within the scan are not hovered again during verification. There is no partial-season state or episode crawler: Buy/free-trial offers and missing evidence remain Unknown. No receipt, acquisition date, episode ownership, API contract or account evidence is invented. Inferred completion remains additive.

**Follow-up live and saved evidence:** The revised inner-artwork sample `(5)` automatically recognized 3/3 purchases; combined physical/automatic observations recognized 10 movie and 5 season purchases. The full read-only export `(6)` then found 302 movies and 41 TV titles, recognized 323 purchases, and left 20 unconfirmed, with all 343 identities independently revisited at pass 38. The subsequent user-provided backup retains all 343 source records: 302 movies and 21 TV products Owned, 20 TV products Unknown. All 20 have empty saved ownership-evidence labels, so this backup cannot distinguish Buy offers from purchase labels rejected during scanning. The user reports approximately six episode-only Buy/Free trial or buy products, one Included with Prime product, one product without purchase wording, and positive purchase labels on the remainder. These are not imported ownership assignments.

**Classification correction implemented in `aa5c89a`:** The added numeric-season gate incorrectly rejected positive labels on TV products without a numeric Season title; 15 of the 20 titles do not satisfy that gate. Raw positive labels could subsequently be lost when Unknown observations replaced them. That gate was removed; explicit purchases apply to the exact source ID. The reported "Included with Prime" wording is recognized as Subscription availability. A purchase may coexist with Prime availability; a purchase/rental contradiction remains unconfirmed. Buy/free-trial offers and absent labels remain Unknown. The user now reports that purchased titles classify correctly; no ownership was assigned from the backup. Revised automatic defaults and Chrome parity still require live validation.

**Purchase versus Prime precedence:** Owned represents a purchase of this exact provider product, while Included with Prime is an observation of subscription availability, not a denial of purchase. Both labels are preserved in the existing `metadata.ownershipEvidence` string using an explicit separator; no schema or backup-format change is introduced. Same-scan observations and both additive/confirmed persistence paths retain Owned after Prime-only or missing-label observations. Prime-only products do not become Owned without a purchase observation. Other source IDs, including same-title products, stay independent. Manual ownership reviews remain authoritative; a purchase/rental contradiction remains unresolved rather than being promoted.

**Blue Bloods live observation:** The user initially saw Included with Prime on Season 2, opened the title's episode list, and subsequently saw a persistent You purchased this label. This confirms why Prime availability must not downgrade prior purchase evidence. GL does not open episode lists or infer purchases from this anecdote; it records the labels actually exposed on each card.

**Release UI and troubleshooting access:** The ordinary panel retains account/profile controls plus Quick update and Full rescan. It has no purchase-detection checkbox or Scan diagnostics disclosure. Normal progress and success messages describe checking purchase information, saved titles and retained earlier titles without scroll-pass/sweep/hover terminology. The general Settings timing export is for worker/UI timings and has no existing bridge to the provider page's local DOM evidence. A new bridge is unnecessary here. Internal `GalacticAmazonVideo.getDiagnostics()`, `checkPurchaseLabels()` and read-only `fetchAmazonVideoLibrary(..., null, {readOnly:true})` remain available in the extension's isolated content-script context. Exports contain only bounded counters, element types and timings: no titles, product IDs, account IDs or credentials.
