The requested Steam B4 label collides with the existing Amazon Video B4 above.
Use **B4-Steam** here without renumbering or reopening the Amazon Video task.

**Recovered cause:** Timing exports 10 and 11 both report 1,112 indexed application
IDs and 159 title candidates in two HTTP 200 requests. Export 10 classified 143
as absent because its parser could not correlate the failure rows. Export 11
correctly correlates all 143 as unavailable: result 15 and `visible:false`, zero
absent IDs, malformed rows or failed requests. The separate sample retains 20
unavailable IDs and all 16 other-type IDs (types 6:3, 7:1, 11:6, 14:6). The complete
143-ID set was not exported, so exact historical set equality cannot be proved.
This establishes the same failure family, not 143 delisted games. Underlying
game/DLC/tool/demo/server/region classifications remain unknown. Six earlier
public samples yielded no usable app-details metadata; two retained Community
pages. Missing public metadata is not lost ownership.

**Ownership evidence:** The signed-in Store's one-response `rgOwnedApps` index
supplies source identity/access evidence, not names. Valve's
[Store client](https://store.fastly.steamstatic.com/public/javascript/dynamicstore.js)
also distinguishes `rgMasterSubApps` (subscription access such as EA Play) and
`rgAutoGrantApps` (automatically granted apps). GL honors these as Subscription
and Unknown rather than permanently Owned; ordinary indexed access uses Owned.
Explicit user corrections remain authoritative. The historical exports did not
retain those optional flags, so they cannot prove permanent ownership of every
one of the 143. No flags or contradictory evidence are invented when absent.
This is not a claim to enumerate every historical Steam license/package.

**Implementation:** Normal catalog/source items require a real title and media
type. Missing or unsupported metadata instead persists as validated IDs/outcomes
in the existing Steam profile's `state.syncState.applications`, with explicit
access exceptions and earlier observed IDs absent from the current index. No
fake game titles, media categories, acquisitions or dates are created. Named
unsupported entries retain supplied type/name without speculative mapping.
Full import validates the complete indexed set against readable records plus
metadata outcomes and the original account-bound snapshot contract, then reuses
additive reconciliation under the same lease. Metadata failure or absence from
a subsequent index never retires a saved title or manufactures a refund. Quick
updates retry pending IDs, including saved records whose metadata failed; later
usable metadata creates/refreshes one normal account/App-ID source. Access flags
can update an existing title even when its metadata lookup is skipped. Existing
acquisition dates and source metadata survive sparse observations.

Ownership-list network/authentication/JSON failures, invalid IDs, malformed
access arrays and explicit incomplete/continuation signals still stop before
saving. Empty indices do not establish that every purchase disappeared. Title
network failures, HTTP 429 and HTTP 5xx get one retry after 500 ms. Authentication,
malformed title responses and explicit unavailable placeholders are not retried
within that attempt; all unresolved entries remain eligible for a later scan.
No public catalog crawl, new endpoint, permissions, schema or credential workflow.
Valve's [GetOwnedGames API](https://partner.steamgames.com/doc/webapi/IPlayerService#GetOwnedGames)
requires an API key and Steam ID and is not a drop-in browser-session fallback.

**Compatibility/UI:** Old backups without the optional Steam state still load;
new backups round-trip it through existing validation. No delete/reimport or
forced migration. Earlier extension versions are not promised lossless downgrade
restore of the new optional state. Ordinary counts are named games/DLC; remaining
title/type gaps are explained separately without labeling the whole import a

[Steam troubleshooting](https://store.steampowered.com/?gl-steam-diagnostics=1)
to retain timing/private-sample controls without DevTools. The diagnostic sample

### B1 termination protocol and live retest

**Confirmed history:** The first Firefox Full rescan incorrectly certified 150 movies + 30 TV titles. The user manually counted 302 movies + 41 TV shows; Amazon did not report 343. An initial read-only export found 343 across 19 passes, including a two-pass plateau at 180. A later Full rescan saved all 343, while Quick update after the bad baseline had found no additions. The format-3 export then found all 343 by pass 14, observed no further discoveries in the remaining 236 passes, and ended unconfirmed at pass 250. The older Chrome backup has 339 distinct records (298 movies/41 TV titles); it is historical comparison evidence, not a completion oracle.

**Root causes:** The original code confused a current scroll boundary plus three quiet polls with the collection's terminal boundary. `d1ba434` removed that unsafe inference but made a provider total mandatory; the real page supplied no recognized total, so normal convergence could never finish. Full scans and read-only checks share traversal, so the earlier different outcomes do not establish different parsers. Exact timing of the unexported first failure remains unknown.

**Available evidence and limits:** The latest live export uses the document scroller, reports no separate vertical containers, has only 67 cards in the final DOM despite 343 cumulative IDs, and shows zero recognized loading/Next controls at the end. Earlier exports show scroll-range extensions after apparent exhaustion. This supports asynchronous loading/recycled viewports; it does not reveal the website's internal implementation. Repository inspection shows DOM-card acquisition, not a cursor or application-state adapter. The exports contain no request lifecycle, cursor, structured application state or explicit end-marker contract. No authoritative count, cursor exhaustion or terminal marker has been demonstrated, and absence from these diagnostics is not proof none exists. No speculative API, credential handling or permissions were added.

**Implemented termination protocol:**

1. Traverse overlapping viewports across all detected vertical title lists, accumulating distinct source IDs in memory. A three-poll boundary candidate starts validation; it cannot itself certify completion.
2. At that candidate, scroll back one viewport and attempt to advance beyond the boundary. Check actual movement, range changes, tail membership and pending library controls. New items or range extensions invalidate the candidate and resume discovery.
3. Reset to the start and perform a full verification sweep. Require every previously discovered ID to be revisited, no additional IDs, the same terminal rendered membership and scroll ranges, exhausted relevant containers, and clear loading/continuation checks. New observations restart discovery and validation; conflicting/incomplete verification ends uncertain promptly. Perpetual growth/unstable traversal retains the 250-pass emergency cap.
4. Classify the result explicitly. A consistent, scoped whole-list label matching observed membership can still confirm completion. Without one, successful active probes plus an independently revisitable, converged sweep infer completion. This does not prove arbitrarily late content cannot arrive. No account-specific item or pass count is used in production.

| Outcome | Evidence / termination | Persistence |
| --- | --- | --- |
| Confirmed | Whole-list count reconciles, stable boundary, no pending continuation. No such live count is currently established. | Existing validated full replacement; missing records can move to history under the normal scoped rules. |
| Inferred | Boundary back/forward probe plus complete matching verification sweep, stable ranges/tail, no pending continuation. | Amazon Video's writer validates the snapshot, then uses additive reconciliation under the existing lease/account/stale-save guards. No unseen record is retired. Existing sync-health coverage limitation records this qualification. |
| Uncertain | Verification cannot revisit membership, geometry/continuation disagrees, count conflicts, or emergency budget is reached. | No observations imported or replaced. Read-only checks can return/export partial observations. |
| Failed | Actual extraction/navigation/other operational error. | No observations imported; existing failure reporting remains. |

The qualified inferred path is a practical safe reconciliation, not an authoritative replacement masquerading as certainty. Older unseen entries may remain current until separately confirmed absent; current-versus-history rules are unchanged for confirmed replacements. Source identifiers, manual edits, account boundaries, purchase/rental/access parsing and other providers are unchanged. No schema migration is needed. Quick update remains newest-only and cannot repair older gaps from a bad baseline.

**Diagnostics:** Format 4 retains new/cumulative and movie/TV counts, per-phase scroll target/movement/range, recognized loading controls, boundary-probe results, verification start/end/revisited/missing/new membership counts, range/tail checks, classification and stop reason. No titles, product IDs, account identifiers, URLs or credentials are exported. Read-only checks still create no sync lease or saved library changes.

**Validation:** `node tests/browser.js --release --amazon-video` and the same command with `--firefox` each pass 63 synthetic packaged-browser checks. The delayed-180 fixture does not finish there; the scroll-driven 343-item fixture revisits all identities and terminates through convergence, with test bounds far below 250. Non-revisitable virtual content stays uncertain, and persistent busy/more controls stop via failed verification instead of spinning. Tests cover returning loading indicators, late range extensions, separate scrollers, navigation errors, unchanged repeats and additive preservation. Two worker regressions exercise same-account inferred merges, other-account/provider isolation, stale commits, malformed proofs and confirmed retirement. ### B2 identity, dates and recovery: current implementation

This section supersedes the earlier claim-ID and deduplication descriptions. **Identity strategy:** No stable Amazon transaction, entitlement or product identifier has been established from the available saved data and sanitized page evidence. Do not adopt the DOM ID or numeric row suffix. The shared page/writer helper builds SHA-256 evidence keys from exact NFC/whitespace-normalized title, artwork and product URL paths (known Amazon image resize suffixes reduce to the same asset reference), explicit edition/volume/format/language/publisher/platform evidence, destination and the Collected on calendar date when available. The database's existing provider/profile namespace provides account isolation. Edition words and issue numbers are never stripped. Identical available evidence cannot distinguish two real acquisitions; it is grouped conservatively without inventing transaction multiplicity. Missing-date evidence remains explicitly undated. Changing artwork/title may fragment a fallback group; no fuzzy alias or bibliography is introduced to hide that limitation.

**Dates:** Read Collected on only from the claim's linked details. **Persistence/recovery:** Page scans consolidate repeated evidence before snapshot construction.
