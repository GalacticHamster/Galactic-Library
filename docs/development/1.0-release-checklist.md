# Galactic Library 1.0 release stabilization checklist

Planning checkpoint: October 23, 2026; source baseline `9f97b0e`.

This is one bounded work queue, not authorization to implement its tasks. No library changes, automatic cross-browser merges, version changes, remote operations or publication are authorized by this checklist. Each subsequent implementation needs its own reviewed scope. Keep new live-test defects here as separate reproducible items rather than reopening a general audit.

Evidence labels: **live** means an actual provider session; **fixture** means synthetic inputs; **disposable replay** means saved data tested in an isolated library. Automated passes do not establish live compatibility. An unchecked item remains open even if existing tests pass.

Order: repair B1–B3 and finish I2 live Firefox testing first; compare completed imports in D1 next; inventory wording in U1 afterward; then settle release decisions and final validation. No calendar estimates.

### I1 — Audible historical cause: GL behavior change demonstrated; historical website conditions unknown

**Status:** Current import repaired; user reports 796 legitimate records and authoritative Chrome reconciliation complete. Do not reopen the resolved data repair as a new blocker merely because historical HTML is unavailable.

**Evidence:** Commit `b00681f` (September 30) introduced whole-page Next detection and rejection of repeated pages while Next remained present. Its predecessor `91c4061` stopped successfully when no new IDs appeared. A read-only execution of both historical implementations against identical fixture responses (two unique pages, then a repeated page, with an unrelated Next control) produced:

| Historical implementation | Result on identical input |
| --- | --- |
| `91c4061` | Success: two items, three requests. |
| `b00681f` | Failure on request three: “Audible repeated a page before the library ended; no library changes were saved.” |

This establishes a stricter GL validator exposing overbroad pagination detection; an Audible website change is **not required** to explain success becoming failure. It does not prove the exact historical page-19 markup or whether library size/page structure also changed. No historical response capture establishes an Amazon change. Whole-page `/pd/` extraction and ambiguous Remove-based access inference were separate older defects, not evidence of a recent website change.

**Why tests missed it:** Earlier `tests/run.js` tested item metadata/actions, including the old Remove classification. `tests/provider-snapshots.js` tested rejection of a non-library response, not carousel-versus-library pagination. `tests/importers-fixture.js` mocked fetching, so save/UI tests could pass without exercising real completion detection.

**Existing repairs/evidence:** `8383c65` through `9f97b0e` address scoped pagination, disabled/zero/filter controls, extraction boundaries, access evidence and preservation. `tests/audible-pagination-browser-fixture.js` now exercises these boundaries, repeated pages, long traversal and failure preservation; `tests/audible-rescan.js` covers preservation and access/ASIN handling. Disposable production-writer replay moved the 20 wishlist records to history, retained 796 current records and their stable references, and preserved unrelated data. That replay is distinct from the user's live reconciliation report.

**Next action / acceptance:** Retain this causal explanation and add the historical success-versus-rejection reproduction to the next focused regression task if it is not already equivalent to current tests. Record the tested build and live completion summary in I2. Close historical investigation with the explicit uncertainty above unless an existing historical capture supplies more evidence; no speculative Amazon explanation. Depends on no new repair.
