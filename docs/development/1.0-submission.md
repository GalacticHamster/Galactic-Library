## Data and permission explanations

GL stores validated provider records, account labels, supported purchase/access evidence, contents/reviews and corrections locally. Provider requests use supported signed-in sites; local companions exchange bounded matching data and explicitly authorized saved purchases. There is no developer-operated library collection or analytics service. Optional Open Library/Google Books requests send bibliographic fields externally. Firefox required data is `none`, with optional `websiteContent` and `authenticationInfo`; the latter applies to the configured Google key. Grants are explicit and revocable. AMO notes and the public policy must describe this; do not claim Mozilla has formally approved the classification.

Storage/unlimitedStorage support large private libraries; scripting runs supported provider tasks; alarms support jobs/sync/reminders; optional notifications support reminders. Named provider and metadata host access supports those features. No new ordinary host/API permissions were added for metadata consent.

Suggested listing description: "Bring supported digital libraries together in one private, browser-local catalog. Optional Humble Library/Fanatical Library companions add bundle checks and consented purchase sync. Optional online book lookups share bibliographic information with Open Library or Google Books after Firefox permission. Supported provider scopes and access uncertainty remain visible."
