# Comic/manga enrichment

Database schema 6 retains candidate reviews, source-selection history and reviewed local/source metadata in backups. Schemas 1–5 remain readable; backup format is still version 1. Provider data stays intact; enrichment is separate source evidence.

Google Books automatic selection requires one unambiguous candidate, compatible identifiers and edition evidence, and a validated ISBN or matching title and author. Numbered volumes cannot automatically use another volume or an unnumbered series; substantive parenthetical numbers and qualifiers are retained. Multiple plausible results require review, even when title and author agree.

All books missing Google Books edition metadata can enter discovery, including records without authors. Searches use available series/unit and publisher evidence. Authorless discoveries require human edition confirmation. Candidate rows show title, subtitle, authors, publisher, language and ISBNs; known edition conflicts block selection. Unselected candidates remain available for later review and backup/restore unless explicitly dismissed.

Open Library selections are work evidence. Newly confirmed work authors and publishers can improve subsequent searches. Its aggregate work ISBN list never identifies the owned edition. Legacy selections without an explicit approval remain visible but do not silently supply authoritative authors; review and apply them again to confirm.

Genre hints, work identity, edition metadata, creators and verified contents have separate completion states. A genre hint cannot exclude a book from edition enrichment. Lookup success does not prove ownership or complete collected contents.

Each source selection records its source identity/URL, retrieval date, match basis and human-approval state. The evidence table associates every stored field with that source and displays differing provider values. Undo restores the previous source selection without altering provider fields. An older selection cannot undo a newer one. Record references prevent a delayed selection from applying to another account's record with a reused provider ID.

Automated lookups checkpoint up to five outcomes with one database write and one UI refresh per batch. The same write stores progress and source selections, so a failed write does not advance the cursor. A worker-owned two-minute lease prevents competing options pages from running or resetting an active job. Heartbeats renew it while scanning; a closed page can be resumed after expiration. Clear and restore invalidate the job. Each checkpoint also checks the current record references, titles and source observation dates, and skips records changed during the lookup. Public enrichment requests are serialized, spaced by at least 1.2 seconds, and time out after 20 seconds.

Kindle contents extraction preserves abbreviations such as `Vol. One` and `J.M.S.`. Results distinguish a found statement, no statement, an unavailable product page, and a temporary failure. Statements additionally carry extractor/parser versions and full/partial/failed parsing outcomes; parsing is a proposal, not verified ownership coverage. Kindle discovery accepts every supported Kindle book, independent of comic classification, and offers normal scan, retry, explicit rescan and local reparse. See [Kindle contents discovery](kindle-contents-discovery.md). Temporary failures remain eligible for retry and store only a safe failure category. CAPTCHA/sign-in responses are failures rather than empty contents. Persistent record references bind these results to the original library/profile record.

## Local and identifier sources (GL-25)

In Library item Details, expand **Book information**, then **Use a file or publisher page**. Import `ComicInfo.xml`, an EPUB, or extracted OPF metadata. Files stay local. The adapter retains title, writers, contributor roles, series/run/unit, language, publisher, ISBN and an explicit contents statement where available. XML DTDs/entities are rejected. EPUB import reads the ZIP directory, container and package metadata rather than loading chapters or images; directories, compressed/uncompressed metadata, paths and checksums are bounded and checked. Encrypted, multi-disk and ZIP64 archives are unsupported. Browsers without raw-deflate decompression can import extracted OPF instead.

ComicInfo `Volume` describes the comics series run, while `Number` identifies the book. This adapter uses `Number` as an issue, or a volume for explicitly marked manga, and leaves those proposals for review. See the [ComicInfo schema documentation](https://anansi-project.github.io/docs/comicinfo/documentation). EPUB collection positions can represent a hierarchy; decimal positions are retained as no inferred volume rather than guessed issue/volume identity. See [EPUB 3.3 package metadata](https://www.w3.org/TR/epub-33/).

**Find Open Library edition by ISBN** looks up a checksum-valid identifier and fetches bounded author references. The edition key/URL stays distinct from a work key. Existing Google Books discovery also prioritizes validated ISBNs. Work-level aggregate ISBNs remain unsuitable for edition ownership. See [Open Library Books API](https://openlibrary.org/dev/docs/api/books).

For publisher evidence, paste the edition title, source page, relevant bibliographic fields and original contents statement. This is an explicitly cited manual proposal, not a publisher-page scraper. Source URLs are sanitized. Provider fields are never overwritten, and file import or lookup never establishes ownership or verifies collected contents by itself.

## Enrichment workbench (GL-31)

Open **Book information** under Library for bulk **Review book suggestions**, or review an individual item in [item details](item-details.md). Separate queues show missing genre/work/edition/creator stages, candidate or ambiguous matches, edition conflicts, failed/empty lookups, all unverified contents statements (fully parsed, partially parsed or unresolved), changed discoveries and current undoable source selections. Only active library records appear. Filter by queue and title; fifty entries per page keeps controls bounded and lets you reach every result.

Choose a candidate and explicitly confirm its work or edition before **Apply selected candidates**. Review up to fifty at once; a single worker write applies the entire batch, and any stale record or known conflict rejects all selections. Conflicts between two selected edition sources also reject the batch. Open Library work approval does not establish an edition. **Dismiss selected reviews** removes pending proposals. **Undo selected enrichments** restores previous selections in one write and leaves provider data and ownership intact; stale undo requests fail atomically.

Failed Google Books/Open Library discovery can be retried from the queue. Temporary Kindle contents failures link back to the item and explain that retry belongs in the signed-in Kindle panel. **Review library item** opens the exact current item's Book information section in ordinary Library. Contents queue entries open that exact record in Contents. Filters are cleared only when needed to locate a record outside the current view. Original unparsed contents stay available for correction; only separately saved verified contents enter coverage.
