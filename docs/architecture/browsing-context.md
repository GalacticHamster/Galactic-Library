# Library and Contents browsing context

This is private UI state, separate from schema-13 library data, identity, access, source history and backups.

`ui-preferences.js` defines one authoritative `browse` object: search, media, provider, account, genre, access, reading, series, sort, result page and item anchor. `library` contains only information/DLC filters; `contents` contains only contents status. The bulk `books` maintenance view remains independent. Validation migrates old full Library preferences once, and the preference writer merges partial shared updates without restoring a second common state.

Both collection views reuse the loaded committed snapshot and the same `library-browse.js` projection/query/sort functions. All common record predicates must qualify one provider record. Contents adds book eligibility and its status predicate before grouping/sorting; account rows stay distinct. Search relevance precedes the selected sort. Library pages count canonical groups; Contents pages count qualifying book/account records. Both use the same private page-size preference (20, 50, 100 or 200, default 50), so each list renders at most that many cards. Catalog, account and review counts remain distinct.

Switching views anchors to the inspected exact record when available, otherwise the first visible canonical group in Library or exact record in Contents. The destination finds that anchor in its own filtered canonical ordering. Equal one-record populations/order therefore have equal page boundaries. Multiple accounts can shift Contents page boundaries; the exact qualifying record anchor remains the link between the two views. If the anchor no longer qualifies, the previous page is clamped to the destination range, or zero for an empty result. Workspace-specific filters are retained and identified, not translated into another meaning.

Origin-aware reviews retain a bounded view, item reference and scroll in the current tab's history entry. Back restores the real Library or Contents origin; the collection list remains an explicit separate destination. History Back/Forward and reload restore that context. A copied record fragment without origin defaults to Contents results. UI history stores no source text or record objects. It does not invent access, a shared review or a transaction.

`contents-display.js` reads human entries or interprets only an already saved bounded parser-input string for a visible book. A 200-record cache is scoped to the database object and clears on snapshot replacement. It never selects a new source, visits manifest blocks, scans the full corpus or supplies matching/index evidence. Unsupported interpretations fall back to saved text. Compression preserves series, run, language, unit kind and excerpt/full scope; numeric component names remain literal. A canonical preview names its selected qualifying account, preferring reviewed material; Details exposes every account separately.

`draft-guard.js` retains tab-local form DOM and guards consequential navigation. A successful operation clears only its initiating form. A failed operation retains it. Reconciliation compares relevant saved inputs; stale actions are blocked until explicit discard/reload. Library rebuilding is deferred while item drafts remain open. Contents also retains orphaned editors for reference when their record disappears. The existing authoritative writer still validates every save; this is not a new database compare-and-swap protocol. Drafts are neither backed up nor crash recoverable. Browser unload prompts depend on platform user-activation rules.

See [Library browsing](../user-guide/library-browsing.md), [Contents](../user-guide/contents-workspace.md) and [item Details](../user-guide/item-details.md).

Shared pagination presents one page/range state in top and bottom rows. Only the upper range announces changes. Page-size changes reset the current browsing page/anchor and persist the separate root UI preference immediately; ordinary view persistence retains its existing debounce. Navigation scrolls to the upper results controls after rendering and respects reduced motion. Search/filter/sort reset to page one; removed results clamp to a valid page. Preferences remain outside the library database and backups.
